# Feature Specification: 뱅킹 UI 개선 및 기능 확장

**Feature Branch**: `007-banking-features-v2`
**Created**: 2026-01-30
**Status**: Draft
**Input**: User description: "모든 금액 입력 버튼 수정 (5만원/1만원/5천원/천원)(사회복지기금 15만원은 유지), 자산 현황 만원 단위 표시 구현, 알림 시스템 및 개인 거래 내역 기능 추가, 은행 수령 기능 추가 (복권, 우승상금 등), 자산 매각(반액 대매출) 기능 구현, 호스트 게임 종료 시 전체 동의 프로세스 추가"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 금액 입력 버튼 단위 변경 (Priority: P1)

플레이어가 거래 시 금액을 입력할 때, 현재 10만/5만/1만 단위 버튼 대신 5만원/1만원/5천원/천원 단위의 버튼을 사용하여 더 세밀한 금액 조절이 가능합니다. 단, 사회복지기금 기부 화면에서는 기존 15만원 버튼이 유지됩니다.

**Why this priority**: 모든 거래의 핵심 입력 방식을 변경하는 기능으로, 사용자 경험에 가장 직접적인 영향을 미칩니다.

**Independent Test**: 거래 모달을 열어 금액 버튼들이 5만/1만/5천/천원 단위로 표시되고 정상 동작하는지 확인하여 테스트할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** 플레이어가 송금 거래 모달을 열었을 때, **When** 금액 입력 버튼을 확인하면, **Then** +5만, +1만, +5천, +천원 및 -5만, -1만, -5천, -천원 버튼이 표시됩니다.
2. **Given** 플레이어가 복지기금 기부 화면을 열었을 때, **When** 금액 입력 버튼을 확인하면, **Then** +15만원 버튼이 상단에 유지되고, 나머지는 5만/1만/5천/천원 단위로 표시됩니다.
3. **Given** 플레이어가 +5천원 버튼을 클릭했을 때, **When** 현재 금액이 0원이면, **Then** 금액이 5,000원으로 변경됩니다.
4. **Given** 플레이어가 -천원 버튼을 클릭했을 때, **When** 현재 금액이 1,000원 미만이면, **Then** 금액은 0원으로 유지됩니다 (음수 방지).

### User Story 2 - 자산 현황 만원 단위 표시 (Priority: P1)

플레이어가 대시보드와 랭킹에서 자산 현황을 볼 때, 금액이 만원 단위로 간결하게 표시되어 가독성이 향상됩니다. 예: 1,500,000원 → 150만원

**Why this priority**: 모든 화면에서 금액 표시 방식을 개선하여 사용자가 자산 상황을 빠르게 파악할 수 있게 합니다.

**Independent Test**: 대시보드에서 현금 및 자산이 만원 단위로 표시되는지 확인하여 테스트할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** 플레이어의 현금이 1,500,000원일 때, **When** 대시보드를 확인하면, **Then** "150만원"으로 표시됩니다.
2. **Given** 플레이어의 총 자산이 25,300,000원일 때, **When** 랭킹 목록을 확인하면, **Then** "2,530만원"으로 표시됩니다.
3. **Given** 플레이어의 현금이 5,000원일 때, **When** 대시보드를 확인하면, **Then** "0.5만원"으로 표시됩니다.
4. **Given** 금액이 0원일 때, **When** 화면에 표시되면, **Then** "0원"으로 표시됩니다.

---

### User Story 3 - 개인 거래 내역 조회 (Priority: P2)

플레이어가 자신의 거래 내역을 조회하여 게임 중 발생한 모든 금전 거래(송금, 수령, 납부, 매입/매각 등)를 시간순으로 확인할 수 있습니다.

**Why this priority**: 플레이어가 자신의 재정 흐름을 추적하고 게임 전략을 세우는 데 도움을 주는 중요한 정보 제공 기능입니다.

**Independent Test**: 거래 내역 버튼을 클릭하여 본인의 모든 거래가 시간순으로 표시되는지 확인하여 테스트할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** 플레이어가 대시보드에 있을 때, **When** 거래 내역 버튼을 클릭하면, **Then** 본인과 관련된 모든 거래 목록이 표시됩니다.
2. **Given** 거래 내역 화면이 열려 있을 때, **When** 목록을 확인하면, **Then** 각 거래의 유형, 금액, 상대방, 시간이 표시됩니다.
3. **Given** 새로운 거래가 발생했을 때, **When** 거래 내역을 새로고침하면, **Then** 최신 거래가 목록 상단에 추가됩니다.

---

### User Story 4 - 알림 시스템 (Priority: P2)

플레이어가 게임 중 중요한 이벤트(거래 수신, 투표 요청, 게임 상태 변경 등)에 대해 실시간 알림을 받아 게임 진행 상황을 놓치지 않습니다.

**Why this priority**: 기존 toast 알림을 확장하여 더 체계적인 알림 경험을 제공합니다.

**Independent Test**: 다른 플레이어가 송금했을 때 알림이 표시되는지 확인하여 테스트할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** 다른 플레이어가 본인에게 송금했을 때, **When** 거래가 완료되면, **Then** "OOO님이 XX만원을 보냈습니다" 알림이 표시됩니다.
2. **Given** 새로운 투표가 시작되었을 때, **When** 투표 이벤트가 발생하면, **Then** 투표 시작 알림이 표시됩니다.
3. **Given** 플레이어가 알림을 받았을 때, **When** 알림 영역을 확인하면, **Then** 읽지 않은 알림 개수가 표시됩니다.

---

### User Story 5 - 은행 수령 기능 (Priority: P2)

플레이어가 은행으로부터 특별 수령(복권 당첨금, 우승 상금, 보너스 등)을 받을 수 있습니다. 호스트가 금액과 사유를 지정하여 특정 플레이어에게 지급합니다.

**Why this priority**: 게임의 다양한 이벤트(복권, 우승 등)를 지원하여 게임 플레이의 재미를 높입니다.

**Independent Test**: 호스트가 특정 플레이어에게 은행 수령을 실행하고 해당 플레이어의 잔액이 증가하는지 확인하여 테스트할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** 호스트가 은행 수령 기능을 선택했을 때, **When** 수령 대상 플레이어와 금액, 사유를 입력하면, **Then** 해당 플레이어에게 금액이 지급됩니다.
2. **Given** 플레이어가 은행 수령을 받았을 때, **When** 대시보드를 확인하면, **Then** 현금 잔액이 수령 금액만큼 증가합니다.
3. **Given** 은행 수령이 완료되었을 때, **When** 거래 내역을 확인하면, **Then** "은행 수령: [사유]" 형태로 기록됩니다.

---

### User Story 6 - 자산 매각 (반액 대매출) 기능 (Priority: P2)

플레이어가 보유한 부동산 자산을 매각하여 현금화할 수 있습니다. 매각 시 자산 가치의 50%(반액)를 현금으로 받습니다.

**Why this priority**: 플레이어가 현금이 부족할 때 자산을 현금화하는 전략적 옵션을 제공합니다.

**Independent Test**: 부동산을 보유한 플레이어가 매각을 실행하고 자산 가치의 50%가 현금으로 전환되는지 확인하여 테스트할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** 플레이어가 100만원 가치의 토지를 보유하고 있을 때, **When** 해당 토지를 매각하면, **Then** 50만원이 현금으로 지급되고 토지는 사라집니다.
2. **Given** 플레이어가 자산 매각을 선택했을 때, **When** 보유 자산 목록이 표시되면, **Then** 각 자산의 현재 가치와 매각 시 받을 금액(50%)이 표시됩니다.
3. **Given** 매각이 완료되었을 때, **When** 거래 내역을 확인하면, **Then** "자산 매각: [자산명] - [매각금액]" 형태로 기록됩니다.
4. **Given** 플레이어가 보유 자산이 없을 때, **When** 자산 매각을 시도하면, **Then** "매각할 자산이 없습니다" 메시지가 표시됩니다.

---

### User Story 7 - 호스트 게임 종료 시 전체 동의 프로세스 (Priority: P3)

호스트가 게임 종료를 요청할 때, 모든 플레이어의 동의를 받아야 게임이 종료됩니다. 이를 통해 게임이 갑작스럽게 종료되는 것을 방지합니다.

**Why this priority**: 게임 경험의 공정성을 보장하는 기능으로, 핵심 게임플레이보다는 부가적인 안전장치입니다.

**Independent Test**: 호스트가 게임 종료를 요청하고 모든 플레이어가 동의해야만 게임이 종료되는지 확인하여 테스트할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** 호스트가 게임 종료 버튼을 클릭했을 때, **When** 종료 요청이 전송되면, **Then** 모든 플레이어에게 게임 종료 동의 투표가 시작됩니다.
2. **Given** 게임 종료 투표가 진행 중일 때, **When** 모든 플레이어가 동의하면, **Then** 게임이 종료되고 최종 정산 화면이 표시됩니다.
3. **Given** 게임 종료 투표가 진행 중일 때, **When** 한 명이라도 거부하면, **Then** 게임 종료가 취소되고 게임이 계속됩니다.
4. **Given** 게임 종료 투표가 진행 중일 때, **When** 제한 시간(60초) 내 응답하지 않은 플레이어가 있으면, **Then** 미응답은 동의로 간주됩니다.

---

### Edge Cases

- 금액 버튼 연속 클릭 시 금액이 음수가 되지 않도록 처리
- 만원 단위 표시 시 1만원 미만 금액은 소수점 만원 단위로 표시 (예: 0.5만원)
- 거래 내역이 없는 플레이어가 거래 내역을 조회할 때 빈 상태 안내
- 은행 수령 시 호스트가 자기 자신에게 지급하는 경우 허용 (호스트도 게임 참여자)
- 자산 매각 중 다른 플레이어가 해당 자산에 대한 거래를 시도할 때 충돌 방지
- 게임 종료 투표 중 플레이어가 연결이 끊어진 경우 처리
- 호스트가 게임 종료 투표 중 연결이 끊어진 경우 투표 취소 또는 새 호스트 승계

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 거래 모달에서 +5만, +1만, +5천, +천원 및 -5만, -1만, -5천, -천원 금액 버튼을 제공해야 합니다.
- **FR-002**: 시스템은 복지기금 기부 화면에서 기존 +15만원 버튼을 유지해야 합니다.
- **FR-003**: 시스템은 모든 금액 표시를 만원 단위로 변환하여 표시해야 합니다 (예: 1,500,000원 → 150만원).
- **FR-004**: 시스템은 1만원 미만 금액을 소수점 만원 단위로 표시해야 합니다 (예: 5,000원 → "0.5만원", 3,500원 → "0.35만원").
- **FR-005**: 시스템은 플레이어별 거래 내역을 저장하고, 대시보드에 별도 거래내역 버튼을 통해 전체 내역을 스크롤로 조회할 수 있는 기능을 제공해야 합니다.
- **FR-006**: 시스템은 거래 내역에 거래 유형, 금액, 상대방, 시간을 포함해야 합니다.
- **FR-007**: 시스템은 중요 이벤트(거래 수신, 투표, 게임 상태 변경)에 대해 실시간 알림을 표시하고, 4초 후 자동으로 사라지게 해야 합니다.
- **FR-008**: 시스템은 읽지 않은 알림 개수를 표시해야 합니다.
- **FR-009**: 시스템은 호스트가 특정 플레이어(본인 포함)에게 은행 수령(복권, 우승상금 등)을 지급할 수 있는 기능을 제공해야 합니다.
- **FR-010**: 시스템은 은행 수령 시 금액과 사유를 기록해야 하며, 사유는 사전 정의 목록(복권, 우승상금, 보너스 등)에서 선택하거나 "기타"로 직접 입력할 수 있어야 합니다.
- **FR-011**: 시스템은 플레이어가 보유 부동산을 매각하여 자산 가치의 50%를 현금으로 받을 수 있는 기능을 제공해야 합니다.
- **FR-012**: 시스템은 매각 가능한 자산 목록과 예상 매각 금액을 표시해야 합니다.
- **FR-013**: 시스템은 호스트의 게임 종료 요청 시 전체 플레이어 동의 투표를 시작해야 합니다.
- **FR-014**: 시스템은 게임 종료 투표에서 전원 동의 시에만 게임을 종료해야 합니다.
- **FR-015**: 시스템은 게임 종료 투표 제한 시간(60초)을 적용하고, 미응답은 동의로 처리해야 합니다.

### Key Entities

- **Transaction (거래)**: 거래 ID, 유형(TRANSFER, BUY_ASSET, PAY_COST, DONATE, SALARY, WELFARE_RECEIVE, BANK_RECEIVE, SELL_ASSET), 금액, 송금인, 수금인, 사유, 타임스탬프
- **Asset (자산)**: 자산 ID, 유형(LAND, HOTEL, BUILDING, VILLA), 가치, 소유자, 매각 가능 여부
- **Notification (알림)**: 알림 ID, 유형, 메시지, 대상 플레이어, 읽음 여부, 타임스탬프
- **GameEndVote (게임 종료 투표)**: 투표 ID, 요청자(호스트), 투표 상태, 플레이어별 응답, 제한 시간, 결과

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 플레이어가 3번 이내의 버튼 클릭으로 원하는 금액을 입력할 수 있습니다.
- **SC-002**: 자산 현황이 만원 단위로 표시되어 금액 파악 시간이 기존 대비 50% 단축됩니다.
- **SC-003**: 플레이어가 5초 이내에 자신의 거래 내역을 조회할 수 있습니다.
- **SC-004**: 중요 이벤트 발생 시 2초 이내에 관련 플레이어에게 알림이 표시됩니다.
- **SC-005**: 호스트가 30초 이내에 은행 수령 기능을 통해 플레이어에게 금액을 지급할 수 있습니다.
- **SC-006**: 플레이어가 보유 자산을 선택하고 매각을 완료하는 데 20초 이내가 소요됩니다.
- **SC-007**: 게임 종료 투표가 시작되면 60초 이내에 결과가 확정됩니다.
- **SC-008**: 모든 신규 기능이 기존 게임 플레이 흐름을 방해하지 않고 자연스럽게 통합됩니다.

- Q: 1만원 미만 금액 표시 방식? → A: 소수점 만원 단위 (예: 5,000원 → "0.5만원", 3,500원 → "0.35만원")
- Q: 거래 내역 표시 건수 제한? → A: 전체 거래 내역 표시 (스크롤로 모두 조회), 별도 거래내역 버튼으로 접근
- Q: 알림 자동 소멸 여부? → A: 자동 소멸 (4초 후 사라짐)
- Q: 은행 수령 사유 입력 방식? → A: 목록 선택 + 직접 입력 (복권, 우승상금, 보너스 등 목록 또는 "기타"로 직접 입력)
- Q: 호스트 자기 자신 은행 수령 허용? → A: 허용 (호스트도 게임 참여자이므로 자신에게 지급 가능, 거래 내역에 기록)

- 기존 react-hot-toast 기반 알림 시스템을 확장하여 사용합니다.

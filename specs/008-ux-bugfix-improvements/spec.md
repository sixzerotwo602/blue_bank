# Feature Specification: UX 버그 수정 및 기능 개선

**Feature Branch**: `008-ux-bugfix-improvements`
**Created**: 2026-02-01
**Status**: Draft
**Input**: User description: "거래내역 한글화, 은행 수령 개인화, 알림 시스템 수정, 송금/토지매입 자동포커스 제거, 토지/건물 매입 개선, 자산 매각 표시 및 버그 수정, 랭킹 자산 조회, 금액 표시 토글, 100조 제한, 게임종료 취소 버튼"

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 거래내역 한글화 및 상세 기록 (Priority: P1)

사용자가 거래내역을 확인할 때 SALARY, BANK_RECEIVE 등의 영문 표기 대신 한글로 표기되어야 하며, 모든 거래에 대해 지출/소득의 상세 내역(어디서, 무엇으로)이 기록되어야 한다.

**Why this priority**: 가장 기본적인 사용성 개선으로 모든 사용자가 거래내역을 쉽게 이해할 수 있도록 함

**Independent Test**: 거래 발생 후 거래내역 화면에서 한글 표기와 상세 정보 확인 가능

**Acceptance Scenarios**:

1. **Given** 플레이어가 월급를 받았을 때, **When** 거래내역을 조회하면, **Then** "월급"로 표기되고 상세 내역이 표시된다
2. **Given** 플레이어가 은행에서 수령했을 때, **When** 거래내역을 조회하면, **Then** "은행 수령"으로 표기되고 수령 금액이 표시된다
3. **Given** 플레이어가 송금했을 때, **When** 거래내역을 조회하면, **Then** "송금"으로 표기되고 받는 사람 정보가 표시된다
4. **Given** 플레이어가 토지를 매입했을 때, **When** 거래내역을 조회하면, **Then** "토지 매입"으로 표기되고 토지명이 표시된다

---

### User Story 2 - 거래내역 스크롤바 모던 디자인 (Priority: P1)

거래내역이 길어질 경우 표시되는 스크롤바가 현재 UI와 조화롭게 모던한 디자인으로 표시되어야 한다.

**Why this priority**: 시각적 일관성과 사용자 경험 향상을 위한 기본 UI 개선

**Independent Test**: 거래내역이 10건 이상일 때 스크롤바 디자인 확인

**Acceptance Scenarios**:

1. **Given** 거래내역이 화면을 초과할 때, **When** 스크롤이 필요하면, **Then** 현재 UI 테마와 어울리는 모던한 스크롤바가 표시된다
2. **Given** 스크롤바가 표시될 때, **When** 마우스를 올리면, **Then** 시각적 피드백이 제공된다

---

### User Story 3 - 은행 수령 개인화 (Priority: P1)

호스트만이 아닌 개개인이 직접 은행 수령을 할 수 있어야 하며, 받을 플레이어 선택 옵션이 제거되어야 한다.

**Why this priority**: 게임 플레이 흐름의 핵심적인 변경사항으로 모든 플레이어 경험에 영향

**Independent Test**: 일반 플레이어 계정으로 로그인하여 은행 수령 기능 사용 가능 여부 확인

**Acceptance Scenarios**:

1. **Given** 일반 플레이어가 은행 수령 메뉴에 접근할 때, **When** 수령 버튼을 누르면, **Then** 받을 플레이어 선택 없이 본인 계좌로 직접 수령된다
2. **Given** 은행 수령 모달이 열릴 때, **When** UI를 확인하면, **Then** 받을 플레이어 선택 옵션이 존재하지 않는다

---

### User Story 4 - 알림 시스템 동작 복구 (Priority: P1)

현재 동작하지 않는 알림 시스템을 복구하여 플레이어 본인과 관련된 거래/행위 발생 시 적절한 알림이 표시되어야 한다.

**Why this priority**: 사용자 피드백의 핵심 기능으로 거래 성공/실패 인지에 필수

**Independent Test**: 각 거래 유형 수행 후 해당 알림 표시 확인

**Acceptance Scenarios**:

1. **Given** 플레이어가 거래를 성공적으로 완료했을 때, **When** 거래가 처리되면, **Then** "거래 성공!" 알림이 표시된다
2. **Given** 플레이어가 0원 거래를 시도할 때, **When** 유효성 검사가 실패하면, **Then** "금액은 0보다 커야 합니다" 알림이 표시된다
3. **Given** 다른 플레이어가 본인에게 송금했을 때, **When** 송금이 완료되면, **Then** 수신자에게 송금 알림이 표시된다

---

### User Story 5 - 송금하기 자동 포커스 제거 (Priority: P2)

송금하기 모달에서 모바일과 컴퓨터 모두 금액 입력 칸에 자동 포커스되지 않아야 한다.

**Why this priority**: 사용자가 받는 사람을 먼저 선택하는 흐름에 맞는 UX 개선

**Independent Test**: 송금하기 모달 열림 시 금액 입력 칸 포커스 상태 확인

**Acceptance Scenarios**:

1. **Given** 플레이어가 송금하기 메뉴를 선택할 때, **When** 모달이 열리면, **Then** 금액 입력 칸에 자동 포커스되지 않는다
2. **Given** 모바일에서 송금하기 모달을 열 때, **When** 모달이 표시되면, **Then** 키보드가 자동으로 올라오지 않는다

---

### User Story 6 - 토지/건물 매입 자동 포커스 제거 (Priority: P2)

토지/건물 매입 모달에서 모바일과 컴퓨터 모두 금액 입력 칸에 자동 포커스되지 않아야 한다.

**Why this priority**: 사용자가 자산 유형을 먼저 선택하는 흐름에 맞는 UX 개선

**Independent Test**: 토지/건물 매입 모달 열림 시 금액 입력 칸 포커스 상태 확인

**Acceptance Scenarios**:

1. **Given** 플레이어가 토지/건물 매입 메뉴를 선택할 때, **When** 모달이 열리면, **Then** 금액 입력 칸에 자동 포커스되지 않는다

---

### User Story 7 - 토지/건물 매입 자산 정보 입력 개선 (Priority: P1)

토지 매입 시 토지명을 입력할 수 있고, 호텔/빌딩/별장 매입 시 보유 토지 목록에서 선택할 수 있어야 하며, 별장의 경우 갯수(최대 2개)를 선택할 수 있어야 한다.

**Why this priority**: 자산 관리의 핵심 기능으로 매입/매각 연계에 필수

**Independent Test**: 각 자산 유형별 매입 플로우 테스트

**Acceptance Scenarios**:

1. **Given** 플레이어가 토지 버튼을 선택했을 때, **When** UI가 업데이트되면, **Then** 버튼 아래와 금액 입력 칸 사이에 토지명 입력 칸이 표시된다
2. **Given** 플레이어가 호텔/빌딩 버튼을 선택했을 때, **When** UI가 업데이트되면, **Then** 보유 토지 목록이 드롭다운으로 표시된다
3. **Given** 플레이어가 별장 버튼을 선택했을 때, **When** UI가 업데이트되면, **Then** 보유 토지 드롭다운과 갯수 선택 버튼(1개, 2개)이 표시된다
4. **Given** 별장 갯수 선택 시, **When** 갯수를 선택하면, **Then** 최대 2개까지만 선택 가능하다

---

### User Story 8 - 자산 매각 표시 양식 개선 (Priority: P1)

자산 매각 시 보유 자산 목록이 토지명과 건물 유형을 함께 표시하는 새로운 양식으로 변경되어야 한다.

**Why this priority**: 자산 식별의 명확성을 위한 핵심 UX 개선

**Independent Test**: 자산 매각 화면에서 보유 자산 표시 형식 확인

**Acceptance Scenarios**:

1. **Given** 플레이어가 서울 토지를 보유하고 있을 때, **When** 자산 매각 목록을 확인하면, **Then** "서울" + "토지" 형태로 표시된다
2. **Given** 플레이어가 프랑스에 빌딩을 보유하고 있을 때, **When** 자산 매각 목록을 확인하면, **Then** "프랑스 빌딩" + "빌딩" 형태로 표시된다
3. **Given** 플레이어가 독일에 별장 2개를 보유하고 있을 때, **When** 자산 매각 목록을 확인하면, **Then** "독일 별장1" + "별장", "독일 별장2" + "별장" 형태로 각각 표시된다

---

### User Story 9 - 자산 매각 금액 인식 버그 수정 (Priority: P1)

자산 매각 시 금액이 있음에도 "금액은 0보다 커야 합니다" 오류가 발생하는 버그를 수정해야 한다. 만원 단위 표기 변환 과정에서 발생하는 것으로 추정됨.

**Why this priority**: 핵심 기능의 버그로 자산 매각 자체가 불가능한 상태

**Independent Test**: 자산 선택 후 매각하기 버튼 클릭 시 정상 처리 확인

**Acceptance Scenarios**:

1. **Given** 플레이어가 매각할 자산을 선택하고 금액이 있을 때, **When** 매각하기 버튼을 누르면, **Then** 정상적으로 매각이 처리된다
2. **Given** 만원 단위로 금액이 표시될 때, **When** 매각 처리 시, **Then** 올바른 숫자 값으로 변환되어 처리된다

---

### User Story 10 - 실시간 랭킹 자산 현황 조회 (Priority: P2)

랭킹 목록에서 본인 또는 다른 플레이어를 클릭했을 때 해당 플레이어의 자산 현황이 표시되어야 한다.

**Why this priority**: 게임의 재미와 경쟁 요소를 높이는 추가 기능

**Independent Test**: 랭킹에서 플레이어 클릭 시 자산 현황 모달/패널 표시 확인

**Acceptance Scenarios**:

1. **Given** 플레이어가 랭킹 목록을 보고 있을 때, **When** 특정 플레이어를 클릭하면, **Then** 해당 플레이어의 자산 현황(현금, 토지, 건물 목록)이 표시된다
2. **Given** 자산 현황이 표시될 때, **When** 정보를 확인하면, **Then** 보유 토지명, 건물 유형, 현금 자산이 리스팅된다

---

### User Story 11 - 현금 자산 표시 형식 토글 (Priority: P2)

최상단의 내 현금 자산을 클릭하면 표시 형식이 만원 단위와 숫자 단위 사이에서 토글되어야 한다.

**Why this priority**: 사용자 편의성을 위한 추가 기능

**Independent Test**: 현금 자산 클릭 시 표시 형식 변경 확인

**Acceptance Scenarios**:

1. **Given** 현금 자산이 "586만원"으로 표시될 때, **When** 클릭하면, **Then** "5,860,000" 형태로 변경된다
2. **Given** 현금 자산이 "5,860,000"으로 표시될 때, **When** 클릭하면, **Then** "586만원" 형태로 변경된다

---

### User Story 12 - 금액 입력 100조 제한 (Priority: P2)

모든 금액 입력 필드에서 100조 원을 초과하는 금액 입력을 시스템적으로 제한해야 한다.

**Why this priority**: 오버플로우 방지를 위한 시스템 안정성 기능

**Independent Test**: 100조 초과 금액 입력 시도 시 제한 동작 확인

**Acceptance Scenarios**:

1. **Given** 금액 입력 필드에 100조 이하의 금액을 입력할 때, **When** 입력하면, **Then** 정상적으로 입력된다
2. **Given** 금액 입력 필드에 100조를 초과하는 금액을 입력하려 할 때, **When** 입력을 시도하면, **Then** 시스템이 입력을 제한한다

---

### User Story 13 - 게임종료 투표 취소 버튼 (Priority: P2)

게임종료 투표 모달 하단에 게임 종료 취소 버튼을 추가하여 투표를 취소할 수 있어야 한다.

**Why this priority**: 사용자 실수 방지와 게임 흐름 제어를 위한 추가 기능

**Independent Test**: 게임종료 투표 모달에서 취소 버튼 동작 확인

**Acceptance Scenarios**:

1. **Given** 게임종료 투표 모달이 열려있을 때, **When** 하단을 확인하면, **Then** 게임 종료 취소 버튼이 표시된다
2. **Given** 플레이어가 게임 종료에 투표했을 때, **When** 취소 버튼을 누르면, **Then** 투표가 취소된다

---

### Edge Cases

- 거래내역 한글화: 알려지지 않은 거래 유형이 있을 경우 원본 영문 표기 유지 또는 "기타" 처리
- 토지명 중복: 동일 플레이어가 이미 보유한 토지명과 같은 이름 입력 시 중복 오류 표시
- 별장 갯수: 이미 해당 토지에 별장 2개가 있는 경우 추가 매입 불가 처리
- 자산 매각: 보유 자산이 없는 경우 빈 목록 표시 및 매각 버튼 비활성화
- 금액 100조 제한: 복사/붙여넣기로 큰 금액 입력 시도 시에도 제한 적용
- 랭킹 자산 조회: 플레이어가 게임을 나간 경우 조회 불가 처리
- 알림 시스템: 알림이 여러 개 동시에 발생할 경우 순차적으로 표시

## Requirements _(mandatory)_

### Functional Requirements

**거래내역 관련**

- **FR-001**: 시스템은 모든 거래 유형(SALARY, BANK_RECEIVE, TRANSFER, LAND_PURCHASE, BUILDING_PURCHASE, ASSET_SALE 등)을 한글로 표시해야 한다
- **FR-002**: 시스템은 모든 거래에 대해 지출/소득 구분과 상세 내역(대상, 금액, 자산명 등)을 기록해야 한다
- **FR-003**: 거래내역 스크롤바는 현재 UI 테마와 조화롭게 모던한 디자인으로 표시되어야 한다

**은행 수령 관련**

- **FR-004**: 모든 플레이어가 직접 은행 수령을 할 수 있어야 한다 (호스트 전용 아님)
- **FR-005**: 은행 수령 모달에서 받을 플레이어 선택 옵션이 제거되어야 한다

**알림 시스템 관련**

- **FR-006**: 시스템은 거래 성공 시 "거래 성공!" 형태의 알림을 표시해야 한다
- **FR-007**: 시스템은 유효성 검사 실패 시 "금액은 0보다 커야 합니다" 형태의 오류 알림을 표시해야 한다
- **FR-008**: 플레이어 본인과 관련된 모든 거래/행위 발생 시 적절한 알림이 표시되어야 한다

**송금 관련**

- **FR-009**: 송금하기 모달 열림 시 금액 입력 칸에 자동 포커스되지 않아야 한다

**토지/건물 매입 관련**

- **FR-010**: 토지/건물 매입 모달 열림 시 금액 입력 칸에 자동 포커스되지 않아야 한다
- **FR-011**: 토지 버튼 선택 시 토지명 입력 칸이 표시되어야 한다
- **FR-011a**: 토지명은 동일 플레이어 내에서 중복될 수 없으며, 중복 시 오류 메시지를 표시해야 한다
- **FR-012**: 호텔/빌딩/별장 버튼 선택 시 보유 토지 목록이 드롭다운으로 표시되어야 한다
- **FR-013**: 별장 버튼 선택 시 갯수 선택 버튼(1개, 2개)이 추가로 표시되어야 한다

**자산 매각 관련**

- **FR-014**: 자산 매각 목록은 "토지명 + 자산유형" 형태로 표시되어야 한다 (예: "서울" + "토지", "프랑스 빌딩" + "빌딩")
- **FR-015**: 별장이 여러 개인 경우 "독일 별장1", "독일 별장2" 형태로 개별 표시되어야 한다
- **FR-016**: 자산 매각 시 만원 단위 표기를 올바른 숫자 값으로 변환하여 처리해야 한다

**랭킹 관련**

- **FR-017**: 랭킹 목록에서 플레이어 클릭 시 해당 플레이어의 자산 현황이 표시되어야 한다
- **FR-018**: 자산 현황에는 현금, 토지 목록, 건물 목록이 포함되어야 한다

**금액 표시 관련**

- **FR-019**: 상단 현금 자산 클릭 시 만원 단위 ↔ 숫자 단위 토글이 가능해야 한다
- **FR-020**: 모든 금액 입력 필드는 최대 100조 원까지만 입력 가능해야 한다
- **FR-021**: 100조 초과 입력 시도 시 시스템이 입력을 제한해야 한다

**게임종료 관련**

- **FR-022**: 게임종료 투표 모달 하단에 게임 종료 취소 버튼이 표시되어야 한다
- **FR-023**: 취소 버튼 클릭 시 해당 플레이어의 게임종료 투표가 취소되어야 한다

### Key Entities

- **거래내역 (Transaction)**: 거래 유형(한글), 금액, 상세 내역(대상/자산명), 시간, 지출/소득 구분
- **플레이어 자산 (PlayerAsset)**: 토지명, 자산 유형(토지/호텔/빌딩/별장), 갯수(별장의 경우)
- **알림 (Notification)**: 메시지 내용, 유형(성공/오류/정보), 대상 플레이어
- **게임종료 투표 (EndGameVote)**: 투표 플레이어, 투표 상태(찬성/취소)

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 모든 거래 유형이 한글로 표시되고 상세 내역이 포함된다

## Assumptions

- 알림 표시 시간: 기존 react-hot-toast 기본값 유지 (일반 알림 4초, 중요 알림 5초)

- 100조 원 = 100,000,000,000,000 원 (10^14)
- 별장은 하나의 토지당 최대 2개까지만 건설 가능
- 알림은 토스트 형태로 일정 시간 후 자동 사라짐

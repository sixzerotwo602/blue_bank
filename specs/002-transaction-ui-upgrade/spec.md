## User Scenarios & Testing _(mandatory)_

### User Story 1 - 송금 및 결제 후 모달 자동 닫힘 (Priority: P1)

사용자는 송금이나 결제 등의 행위를 완료한 후, 별도의 조작 없이 자동으로 모달이 닫히기를 원합니다.

**Why this priority**: 사용자 경험(UX) 향상을 위해 필수적이며, 연속적인 게임 진행을 매끄럽게 합니다.

**Independent Test**: 송금 기능을 사용하여 완료 시점에 모달이 닫히는 동작만 독립적으로 검증 가능합니다.

**Acceptance Scenarios**:

1. **Given** 사용자가 '송금' 모달에서 금액과 대상을 선택하고 '보내기'를 누른 상태, **When** 송금 로직이 성공적으로 완료되면, **Then** 성공 알림(alert) 이후 모달이 자동으로 닫혀야 한다.
2. **Given** 사용자가 '기부' 모달에서 기부를 완료한 상태, **When** 기부 완료 알림이 뜨고 나면, **Then** 모달이 닫힌 상태여야 한다.

---

### User Story 2 - 금액 입력 시 차감 기능 (Priority: P1)

사용자는 금액을 입력할 때, 버튼을 통해 금액을 더하는 것뿐만 아니라 뺄 수도 있어야 합니다.

**Why this priority**: 금액 수정 시 전체를 지우고 다시 입력하는 불편함을 해소합니다. `ui_ref.md`에 정의된 기능을 준수합니다.

**Independent Test**: 금액 입력 모달을 열고 차감 버튼을 눌러 숫자가 줄어드는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 입력창에 100,000원이 입력된 상태, **When** '-1만' 버튼을 3번 클릭하면, **Then** 입력창의 금액이 70,000원으로 변경되어야 한다.
2. **Given** 입력창에 0원이 입력된 상태, **When** '-1만' 버튼을 클릭하면, **Then** 금액은 0원 이하로 내려가지 않고 0원을 유지해야 한다.

---

### User Story 3 - 자산/비용 섹션 개편 (Priority: P2)

사용자는 자산을 구매할 때 '자산'이라는 포괄적인 용어 대신 '땅'과 '건물'로 구분된 UI를 원합니다.

**Why this priority**: 게임의 몰입도를 높이고, 사용자가 어떤 유형의 자산을 구매했는지 명확히 기록하기 위함입니다.

**Independent Test**: 자산 구매 모달 UI에서 땅/건물 구분을 확인합니다.

**Acceptance Scenarios**:

1. **Given** 메인 대시보드 화면, **When** 화면을 스크롤하여 액션 버튼 섹션을 확인하면, **Then** 섹션 타이틀이나 버튼 설명이 '자산/비용'이 아닌 '땅/건물' 관련 문구로 변경되어 있어야 한다.
2. **Given** '자산 구매' 버튼이 '땅 구매'와 '건물 구매' 또는 내부에서 선택 가능한 형태로 변경됨, **When** 모달이 열리면, **Then** 금액 입력란이 존재해야 한다 (이름 입력란 없음).
3. **Given** 사용자가 금액을 입력하고 구매하면, **Then** 해당 자산의 타입(땅/건물)이 구분되어 처리되어야 한다.

### Edge Cases

- **금액 차감 시 0원 미만 도달**: 금액은 0원 밑으로 내려가지 않아야 함.
- **소지금 초과 금액**: 현재 소지금보다 큰 금액을 입력하고 구매/송금 시도 시, 에러 메시지 표시.

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 시스템은 송금, 자산 구매, 비용 지불, 기부 등 모든 금전적 트랜잭션이 성공적으로 완료된 직후(Alert 확인 후) 해당 모달을 자동으로 닫아야 한다.
- **FR-002**: 금액 입력 컴포넌트(BottomSheet)는 사용자가 금액을 쉽게 조절할 수 있도록 차감 버튼(예: -10만, -5만 등)을 포함해야 한다.
- **FR-003**: 메인 대시보드의 '액션 버튼' 영역을 '땅/건물' 관련 직관적인 명칭과 구조로 변경해야 한다.
- **FR-004**: 자산 구매 모달은 사용자가 구매하려는 자산이 '땅'인지 '건물'인지 구분하여 처리해야 한다.
- **FR-005**: (Deleted - Name input requirement removed)
- **FR-006**: 사회복지기금 수령 요청 시, 사용자가 금액을 입력하지 않고 현재 기금 **전액**을 요청하도록 강제해야 한다 (금액 입력 단계 생략 또는 고정).

### Key Entities _(include if feature involves data)_

- **Player (플레이어)**:
  - **Assets**: 소유한 자산(Asset)의 목록 (Array/List)
  - **AssetValue**: 소유 자산들의 가치 총합

- **Asset (자산)**:
  - **Type**: 땅(Land) 또는 건물(Building)
  - **Value**: 자산 가치 (구매 금액)
  - **CreatedAt**: 취득 시점

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 모든 모달은 트랜잭션 성공 후 사용자 추가 조작 없이 닫혀야 한다 (Test Pass Rate 100%).
- **SC-002**: 사용자는 키패드를 쓰지 않고 '+/-' 버튼만으로 155,000원 등 복합적인 금액을 5초 이내에 입력할 수 있다.
- **SC-004**: DB 또는 메모리 저장소에 플레이어의 자산 목록이 배열 형태로 올바르게 저장된다.

## Clarifications

### Session 2026-01-23

- **Q1**: 자산 데이터(땅/건물 이름 등)를 실제 데이터 구조로 저장할까요, 아니면 단순 로그용으로만 쓰고 값(Value)만 합산할까요?
  - **A**: **자산 리스트 저장** - (Updated) 이름 입력은 제외되었으나, 자산의 타입(땅/건물)과 가치를 목록으로 저장하여 관리합니다.

- **Q2**: 건물을 구매할 때, 반드시 보유한 땅 위에 지어야 하나요, 아니면 독립적인 자산(별개 건물)으로 구매할 수 있나요?
  - **A**: **독립적 처리** - UI 복잡도를 낮추기 위해 건물도 땅과 동일하게 독립적인 자산으로 취급합니다.

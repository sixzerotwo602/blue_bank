# 사전 조사: 게임 정산 (Game Settlement)

## 결정 사항

### 1. 확인 모달(ConfirmModal) 재사용

- **결정**: "게임 종료" 확인 창으로 기존 `ConfirmModal` 컴포넌트를 재사용합니다.
- **근거**: 헌법(Constitution)의 **DRY** (중복 배제) 및 **KISS** (단순 유지) 원칙을 따릅니다. 기존 모달은 커스텀 메시지와 제목을 처리하기에 충분히 유연합니다.
- **대안**: 별도의 `GameEndConfirmModal` 생성 (기각: 불필요한 코드 중복).

### 2. 전체 화면 오버레이로 정산 UI 구현

- **결정**: 정산 화면을 작은 모달이 아닌 전체 화면 `fixed` 오버레이(`SettlementView.tsx` 등)로 구현합니다.
- **근거**: 정산은 게임 세션의 최종 단계이므로 중요하게 다뤄져야 하며, 다른 상호작용을 차단해야 합니다. 또한 상세 순위와 내역을 보여주기에 충분한 공간이 필요합니다.
- **대안**: `/settlement` 경로로 리다이렉트 (기각: 라우팅/상태 전달의 복잡성 vs 단순 오버레이).

### 3. 백엔드에서 순위 계산

- **결정**: 백엔드가 최종 순위를 계산하고 정렬된 리스트를 프론트엔드로 전송합니다.
- **근거**: **SoC** (관심사 분리). 승자 결정과 같은 비즈니스 로직은 백엔드/도메인 계층에 속합니다. 프론트엔드는 데이터를 보여주기만 해야 합니다. 보안 측면에서도 클라이언트 측 조작을 방지할 수 있습니다.

### 4. 홈으로 이동

- **결정**: "홈으로 가기" 버튼은 소켓 연결을 끊고(또는 방 퇴장) 클라이언트 라우트를 `/`로 이동시킵니다.
- **근거**: 새로운 세션을 위해 상태를 가장 깔끔하게 초기화하는 방법입니다.

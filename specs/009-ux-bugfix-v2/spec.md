## User Scenarios & Testing *(mandatory)*

### User Story 1 - 송금 모달 UI 오류 수정 (Priority: P1)

플레이어가 다른 플레이어에게 송금하려고 할 때, 송금 대상을 선택하면 관련 없는 버튼이 자동으로 비활성화되어 실수로 잘못된 대상에게 송금하는 것을 방지합니다.

**Why this priority**: 가장 빈번하게 발생하는 휴먼 에러이며, 수정 범위가 작아 빠르게 해결 가능합니다. 사용자의 즉각적인 불편함을 해소합니다.

**Independent Test**: 송금 모달에서 플레이어를 선택했을 때 '은행에게 송금' 버튼이 비활성화되는지 확인하여 테스트 가능합니다.

**Acceptance Scenarios**:

1. **Given** 플레이어가 송금 모달을 열고 다른 플레이어를 송금 대상으로 선택한 상태, **When** 화면을 확인하면, **Then** '은행에게 송금' 버튼이 비활성화(Disabled) 상태로 표시됨
2. **Given** 플레이어가 송금 모달에서 은행을 송금 대상으로 선택한 상태, **When** 화면을 확인하면, **Then** '은행에게 송금' 버튼이 활성화 상태로 표시됨
3. **Given** 플레이어가 송금 대상을 플레이어에서 은행으로 변경, **When** 대상 변경 후, **Then** '은행에게 송금' 버튼이 즉시 활성화됨

### User Story 2 - 게임 종료 투표 취소 동기화 (Priority: P1)

호스트가 게임 종료 투표를 취소했을 때, 모든 플레이어의 화면에서 즉시 투표 모달이 닫히고 알림이 표시되어 혼란을 방지합니다.

**Why this priority**: 게임 진행에 치명적인 영향을 미치는 동기화 버그로, 플레이어 간 상태 불일치가 게임 파토로 이어질 수 있습니다.

**Independent Test**: 호스트가 투표 취소 버튼을 누르면 모든 클라이언트에서 모달이 닫히고 토스트 알림이 표시되는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 호스트가 게임 종료 투표를 시작하여 모든 플레이어에게 투표 모달이 표시된 상태, **When** 호스트가 투표를 취소하면, **Then** 모든 플레이어의 투표 모달이 즉시 닫힘
2. **Given** 투표가 취소된 상태, **When** 각 플레이어 화면에서, **Then** "게임종료 투표가 취소되었습니다" 토스트 알림이 표시됨
3. **Given** 게임 종료 투표 모달이 표시된 상태, **When** 플레이어가 찬성/반대 외의 조작(모달 외부 클릭, ESC 키 등)을 시도하면, **Then** 모달이 닫히지 않고 유지됨

### User Story 3 - 토지 매각 시 건물 일괄 처리 (Priority: P2)

플레이어가 건물이 있는 토지를 매각할 때, 시스템이 건물 존재를 알려주고 일괄 매각 옵션을 제공하여 논리적 오류를 방지합니다.

**Why this priority**: 게임 로직의 무결성을 보장하는 중요한 기능이지만, 발생 빈도가 상대적으로 낮습니다.

**Independent Test**: 건물이 있는 토지의 매각 버튼을 클릭했을 때 경고 팝업이 표시되고, 일괄 매각 시 올바른 금액이 정산되는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 플레이어가 호텔 또는 빌딩이 건설된 토지를 보유한 상태, **When** 해당 토지 매각을 시도하면, **Then** "건물이 포함된 상태입니다. 건물을 먼저 매각하거나 함께 일괄 매각하시겠습니까?" 경고 팝업이 표시됨
2. **Given** 경고 팝업이 표시된 상태에서 '일괄 매각' 선택, **When** 확인 버튼을 누르면, **Then** 토지와 건물이 모두 반값(50%)에 매각되고 해당 금액이 플레이어에게 입금됨
3. **Given** 경고 팝업이 표시된 상태에서 '취소' 선택, **When** 취소 버튼을 누르면, **Then** 팝업이 닫히고 토지와 건물이 그대로 유지됨

### User Story 4 - 은행에서 돈 받기 투표 시스템 (Priority: P2)

플레이어가 은행에서 돈을 받으려고 할 때, 다른 플레이어들의 동의를 거쳐야만 입금이 가능하도록 하여 부정행위를 방지합니다.

**Why this priority**: 게임의 공정성을 높이는 핵심 기능이지만, 기존 프로세스의 변경이 필요해 구현 범위가 큽니다.

**Independent Test**: 은행에서 돈 받기를 요청하면 다른 플레이어들에게 투표 요청이 전송되고, 과반수 동의 시에만 입금되는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 플레이어가 '은행에서 돈 받기' 기능을 사용하려는 상태, **When** 금액을 입력하고 요청 버튼을 누르면, **Then** 다른 모든 플레이어에게 동의/거부 투표 요청이 전송됨
2. **Given** 투표 요청이 진행 중인 상태, **When** 과반수(50% 초과)의 플레이어가 동의하면, **Then** 요청한 금액이 플레이어에게 입금됨
3. **Given** 투표 요청이 진행 중인 상태, **When** 과반수가 거부하면, **Then** 입금이 거절되고 요청 플레이어에게 거절 알림이 표시됨
4. **Given** 대출 기능을 사용하는 경우, **When** 대출을 신청하면, **Then** 투표 없이 즉시 대출이 처리됨 (대출은 예외)

---

### User Story 5 - 거래 취소 기능 (Priority: P3)

플레이어가 실수로 잘못된 금액을 송금했을 때, 거래 내역에서 취소를 요청하고 상대방 동의 후 거래를 되돌릴 수 있습니다.

**Why this priority**: 휴먼 에러 방지에 중요하지만, 구현 복잡도가 높고 다양한 예외 상황 처리가 필요합니다.

**Independent Test**: 거래 내역에서 취소 요청 후 상대방 동의 시 자산이 거래 전 상태로 복원되는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 플레이어가 거래 내역 모달을 열고 최근 송금 거래를 확인하는 상태, **When** 취소 가능한 거래의 '거래 취소' 버튼을 클릭하면, **Then** 상대방에게 취소 요청 알림이 전송됨
2. **Given** 플레이어 간 거래의 취소 요청이 전송된 상태, **When** 상대방이 동의하면, **Then** 양쪽 플레이어의 자산이 해당 거래 전 상태로 복원됨
3. **Given** 은행과의 거래(입금/출금)에서 취소 요청, **When** 취소 버튼을 클릭하면, **Then** 즉시 동의 처리되어 자산이 복원됨
4. **Given** 취소하려는 거래의 자산이 이미 다른 거래로 소진된 상태, **When** 거래 내역을 확인하면, **Then** 해당 거래의 '거래 취소' 버튼이 비활성화되어 있음
5. **Given** 거래가 취소 완료된 상태, **When** 거래 내역을 확인하면, **Then** 해당 거래에 "취소됨" 표시가 나타남

---

### User Story 6 - 자산명 수정 기능 (Priority: P3)

플레이어가 토지 구매 시 입력한 자산명에 오타가 있을 경우, 내 자산 목록에서 직접 수정할 수 있습니다.

**Why this priority**: 사용자 경험 개선에 도움이 되지만, 게임 진행에 필수적인 기능은 아닙니다.

**Independent Test**: 자산 목록에서 토지명을 클릭하여 수정 팝업이 열리고, 새 이름이 저장되는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 플레이어가 내 자산 목록을 보고 있는 상태, **When** 토지명을 클릭하면, **Then** 토지명 수정 팝업이 열림
2. **Given** 토지명 수정 팝업이 열린 상태, **When** 새로운 이름을 입력하고 저장 버튼을 누르면, **Then** 토지명이 변경되고 자산 목록에 반영됨
3. **Given** 수정 팝업에서 빈 이름을 입력, **When** 저장 버튼을 누르면, **Then** "토지명을 입력해주세요" 오류 메시지가 표시되고 저장되지 않음

---

### Edge Cases

- 투표 진행 중 투표자가 게임을 나가면 어떻게 처리하는가? → 해당 플레이어를 제외하고 남은 플레이어 기준으로 과반수 재계산
- 거래 취소 요청 후 상대방이 응답하지 않으면 어떻게 처리하는가? → 요청 후 60초 경과 시 자동 거절 처리
- 동시에 여러 투표가 진행될 경우 어떻게 처리하는가? → 투표는 한 번에 하나만 진행 가능하며, 진행 중일 때 새 투표 요청 시 "진행 중인 투표가 있습니다" 알림 표시
- 건물 일괄 매각 시 정확한 매각 금액 계산 방식 → 토지 원가의 50% + 건물 원가의 50%
- 모든 투표(게임종료/사회복지기금/은행에서 돈 받기)에서 60초 내 미응답 시 어떻게 처리하는가? → 자동 거절로 처리 (적극적 동의 필요 원칙)

## Requirements *(mandatory)*

### Functional Requirements

**이슈 #23: 송금 모달 버튼 활성화 오류**
- **FR-001**: 시스템은 송금 대상이 플레이어로 선택되면 '은행에게 송금' 버튼을 비활성화해야 함
- **FR-002**: 시스템은 송금 대상이 은행으로 선택되면 '은행에게 송금' 버튼을 활성화해야 함
- **FR-003**: 시스템은 송금 대상 변경 시 버튼 상태를 즉시 업데이트해야 함

**이슈 #24: 토지 매각 시 건물 처리**
- **FR-004**: 시스템은 건물이 있는 토지 매각 시도 시 경고 팝업을 표시해야 함
- **FR-005**: 시스템은 일괄 매각 선택 시 토지와 건물을 각각 원가의 50%에 매각해야 함
- **FR-006**: 시스템은 일괄 매각 시 총 매각 금액을 플레이어에게 즉시 입금해야 함

**이슈 #25: 게임 종료 투표 취소 동기화**
- **FR-007**: 시스템은 호스트의 투표 취소를 모든 클라이언트에게 실시간으로 전파해야 함
- **FR-008**: 시스템은 투표 취소 시 모든 플레이어에게 "게임종료 투표가 취소되었습니다" 토스트 알림을 표시해야 함
- **FR-009**: 시스템은 게임 종료 투표 모달이 표시된 동안 찬성/반대 외의 방법으로 모달이 닫히지 않도록 해야 함
- **FR-009-1**: 시스템은 게임 종료 투표에서 60초 내 미응답 플레이어를 자동 거절로 처리해야 함 (기존 동의 처리에서 변경)

**이슈 #26: 거래 취소 기능**
- **FR-010**: 시스템은 거래 내역 모달에 거래별 '거래 취소' 버튼을 제공해야 함
- **FR-011**: 시스템은 플레이어 간 거래 취소 시 상대방의 동의를 요청해야 함
- **FR-012**: 시스템은 은행과의 거래 취소 시 즉시 동의 처리해야 함
- **FR-013**: 시스템은 거래 취소 완료 시 양측 자산을 거래 전 상태로 복원해야 함
- **FR-014**: 시스템은 취소 불가능한 거래(자산이 이미 소진된 경우)의 취소 버튼을 비활성화해야 함
- **FR-015**: 시스템은 취소된 거래를 거래 내역에 "취소됨"으로 표시해야 함

**이슈 #27: 은행에서 돈 받기 투표 시스템**
- **FR-016**: 시스템은 '수령' 용어를 '은행에서 돈 받기'로 변경해야 함
- **FR-017**: 시스템은 은행에서 돈 받기 요청 시 다른 플레이어들에게 투표 요청을 전송해야 함
- **FR-018**: 시스템은 과반수(50% 초과) 동의 시에만 요청 금액을 입금해야 함
- **FR-019**: 시스템은 대출 기능을 투표 대상에서 제외해야 함 (대출은 즉시 처리)
- **FR-019-1**: 시스템은 은행에서 돈 받기 투표에서 60초 내 미응답 플레이어를 자동 거절로 처리해야 함

**기존 사회복지기금 투표 개선**
- **FR-023**: 시스템은 사회복지기금 투표에서 60초 내 미응답 플레이어를 자동 거절로 처리해야 함 (타임아웃 핸들러 신규 구현)

**이슈 #28: 자산명 수정 기능**
- **FR-020**: 시스템은 내 자산 목록에서 토지명 클릭 시 수정 팝업을 표시해야 함
- **FR-021**: 시스템은 유효한 토지명 입력 시 변경 사항을 저장해야 함
- **FR-022**: 시스템은 빈 토지명 입력 시 오류 메시지를 표시하고 저장을 거부해야 함

### Key Entities

- **거래(Transaction)**: 송금자, 수신자(플레이어/은행), 금액, 시간, 상태(완료/취소됨), 취소 가능 여부
- **투표(Vote)**: 투표 유형(게임종료/은행수령동의), 요청자, 참여자 목록, 찬성/반대 현황, 상태(진행중/완료/취소), 제한 시간
- **자산(Asset)**: 소유자, 자산명, 자산 유형(토지/건물), 원가, 건물 포함 여부, **연관 토지 ID (건물인 경우 landId로 소속 토지 참조)**
- **플레이어(Player)**: 닉네임, 현금 잔액, 보유 자산 목록, 호스트 여부

### Entity Relationships

```
Player (1) ──────── (N) Asset
                         │
                         ├── type: 'LAND'
                         │     └── 건물이 이 토지를 참조할 수 있음
                         │
                         └── type: 'BUILDING'
                               └── landId: 소속된 토지의 ID (optional)
```

**건물-토지 관계**: 건물(BUILDING)은 `landId` 필드를 통해 소속된 토지(LAND)를 참조합니다. 토지 매각 시 해당 토지에 연결된 모든 건물을 조회하여 일괄 매각 처리가 가능합니다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 송금 대상 선택 시 버튼 상태가 100ms 이내에 변경됨
- **SC-002**: 호스트의 투표 취소가 모든 플레이어에게 즉시 반영되어 상태 불일치가 발생하지 않음
- **SC-003**: 건물이 있는 토지 매각 시 100% 경고 팝업이 표시되어 실수로 인한 데이터 불일치가 발생하지 않음
- **SC-004**: 거래 취소 기능으로 휴먼 에러로 인한 게임 파토 발생률 감소
- **SC-005**: 은행에서 돈 받기 요청의 100%가 다른 플레이어들의 투표를 거침 (대출 제외)
- **SC-006**: 자산명 수정이 저장 후 500ms 이내에 화면에 반영됨 (네트워크 왕복 포함)

## Assumptions

- 투표 시스템의 과반수 기준은 50% 초과 (예: 4명 중 3명 동의 필요)
- 모든 투표 제한 시간은 60초로 통일 (게임종료/사회복지기금/은행에서 돈 받기/거래 취소)
- 모든 투표에서 60초 내 미응답 시 자동 거절 처리 (적극적 동의 필요 원칙)
- 건물 매각가는 원가의 50%로 고정
- 대출 기능은 기존 시스템을 유지하며 투표 대상에서 제외
- 투표는 동시에 하나만 진행 가능
- 토지명은 빈 문자열이 아닌 경우 모두 유효한 것으로 처리 (특수문자 허용)

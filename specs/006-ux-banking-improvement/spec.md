## User Scenarios & Testing *(mandatory)*

### User Story 1 - 송금 대상 명확화 (Priority: P1)

플레이어가 게임 중 돈을 보낼 때, 다른 플레이어에게 송금하는 것과 은행에 납부하는 것을 명확하게 구분할 수 있어야 한다. 현재 "토지/건물/비용지불" 버튼과 모달이 혼란스러운 UX를 제공하고 있다.

**Why this priority**: 게임의 핵심 기능인 송금이 명확하지 않으면 사용자 경험이 크게 저하됨. 가장 빈번하게 사용되는 기능이므로 최우선 수정 필요.

**Independent Test**: 대시보드에서 "플레이어에게 송금" 버튼과 "은행에 납부" 버튼이 분리되어 있고, 각각 적절한 모달이 표시되는지 확인

**Acceptance Scenarios**:

1. **Given** 송금하기 모달이 열렸을 때, **When** 금액을 입력하면, **Then** 하단에 "플레이어에게 송금"과 "은행으로 송금" 2개의 확인 버튼이 색상 구분되어 표시된다
2. **Given** "토지/건물/비용지불" 버튼이 있을 때, **When** 버튼을 확인하면, **Then** "토지/건물 매입" 으로 텍스트가 변경되어 있다 (비용지불 제거)
3. **Given** TransactionModal이 열렸을 때, **When** BUY_ASSET 타입이면, **Then** "토지/호텔/빌딩/별장" 4버튼 그리드가 표시되어 한 번에 선택 가능하다
4. **Given** 송금하기 모달에서 "은행으로 송금" 버튼을 클릭했을 때, **When** 트랜잭션이 처리되면, **Then** PAY_COST 타입으로 은행에 금액이 납부된다

### User Story 2 - 실시간 뱅킹 자산 정보 개선 (Priority: P1)

플레이어가 실시간 랭킹 목록에서 각 플레이어의 자산 현황을 더 직관적으로 파악할 수 있어야 한다. 현재는 토지/건물 개수만 표시되는데, 평가액도 함께 표시하여 자산 가치를 한눈에 알 수 있게 한다.

**Why this priority**: 게임 전략 수립에 필수적인 정보. 현재 표시되는 정보가 불완전하여 사용자가 정확한 판단을 내리기 어려움.

**Independent Test**: 실시간 랭킹 목록에서 각 플레이어의 토지/건물 개수와 평가액이 함께 표시되는지 확인

**Acceptance Scenarios**:

1. **Given** 실시간 랭킹 목록을 볼 때, **When** 플레이어 정보를 확인하면, **Then** "🏞️ 토지: 3개 (30만원)" 형식으로 개수와 평가액이 함께 표시된다
2. **Given** 실시간 랭킹 목록을 볼 때, **When** 플레이어 정보를 확인하면, **Then** "🏢 건물: 2개 (50만원)" 형식으로 개수와 평가액이 함께 표시된다
3. **Given** 자산이 없는 플레이어를 볼 때, **When** 정보를 확인하면, **Then** "🏞️ 0 | 🏢 0" 형식으로 간략하게 표시된다

### User Story 3 - 건물 유형 구분 표시 (Priority: P2)

플레이어가 보유한 건물의 유형(호텔, 빌딩, 별장 등)을 구분하여 볼 수 있어야 한다. 현재는 모든 건물이 동일하게 표시되어 구분이 불가능하다.

**Why this priority**: 게임 몰입도와 정보 명확성 향상에 도움이 되지만, 핵심 기능은 아님. US1, US2 완료 후 추가 개선 사항.

**Independent Test**: 자산 목록이나 랭킹 목록에서 건물 유형별로 다른 아이콘이나 레이블이 표시되는지 확인

**Acceptance Scenarios**:

1. **Given** 플레이어가 호텔을 보유할 때, **When** 자산 정보를 확인하면, **Then** "🏨 호텔" 레이블과 아이콘이 표시된다
2. **Given** 플레이어가 빌딩을 보유할 때, **When** 자산 정보를 확인하면, **Then** "🏢 빌딩" 레이블과 아이콘이 표시된다
3. **Given** 플레이어가 별장을 보유할 때, **When** 자산 정보를 확인하면, **Then** "🏡 별장" 레이블과 아이콘이 표시된다

**참고**: shared 패키지의 Asset 인터페이스에 buildingType 필드를 추가하고, 백엔드/프론트엔드 전체 수정 진행

---

### User Story 4 - '비용 지불' 용어 명확화 (Priority: P1)

'비용 지불'이라는 모호한 용어를 '은행에 납부'로 변경하여 기능의 목적을 명확히 한다. 이는 US1과 연계된 작업이다.

**Why this priority**: US1과 함께 진행되어야 하는 용어 통일 작업. 사용자 혼란 해소를 위해 필수.

**Independent Test**: 앱 전체에서 '비용 지불' 텍스트가 '은행에 납부'로 변경되었는지 확인

**Acceptance Scenarios**:

1. **Given** TransactionModal의 타이틀을 확인할 때, **When** PAY_COST 타입이면, **Then** "은행에 납부"로 표시된다
2. **Given** 대시보드 버튼을 확인할 때, **When** 관련 버튼이 있으면, **Then** "비용 지불" 대신 "은행에 납부"로 표시된다
3. **Given** 모달 내부 탭을 확인할 때, **When** 기존 "비용 지불" 탭이 있으면, **Then** 해당 탭이 제거되고 별도 "은행에 납부" 버튼으로 분리된다

---

### Edge Cases

- 건물 유형이 정의되지 않은 기존 BUILDING 자산은 어떻게 처리?
  - 기본값으로 "빌딩"으로 표시
- 자산 평가액이 0원인 경우?
  - "0원" 또는 평가액 생략하고 개수만 표시
- 토지/건물이 모두 0개인 플레이어?
  - 간략 표시 유지 ("🏞️ 0 | 🏢 0")

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 대시보드에서 "토지/건물/비용지불" 버튼의 텍스트를 "토지/건물 매입"으로 변경해야 한다
- **FR-002**: 송금하기 모달의 확인 버튼을 "플레이어에게 송금" / "은행으로 송금" 2개로 분리하고 색상을 다르게 표시해야 한다
- **FR-003**: TransactionModal에서 BUY_ASSET 타입일 때 "토지/호텔/빌딩/별장" 4버튼 그리드로 변경해야 한다 (기존 "토지/건물" 2버튼 + "비용 지불" 탭 제거)
- **FR-004**: TransactionModal에서 PAY_COST 타입의 타이틀을 "은행에 납부"로 변경해야 한다
- **FR-005**: RankingList에서 토지/건물의 개수와 평가액을 함께 표시해야 한다
- **FR-006**: shared 패키지에 BuildingType 필드를 추가하고, 백엔드와 프론트엔드 모두 수정하여 건물 유형(호텔/빌딩/별장)을 구분 표시한다

### Key Entities *(include if feature involves data)*

- **TransactionType**: PAY_COST 타입의 용도 명확화 (은행에 납부)
- **Asset**: 현재 'LAND' | 'BUILDING' 타입. 건물 세부 유형 추가 고려
  - buildingType?: 'HOTEL' | 'BUILDING' | 'VILLA' (US3 구현 시 추가)

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 송금하기 모달에서 "플레이어에게 송금"과 "은행으로 송금" 버튼이 색상으로 명확하게 구분되어 표시된다
- **SC-002**: 실시간 랭킹에서 각 플레이어의 토지/건물 개수와 평가액이 한눈에 파악 가능하다
- **SC-003**: 앱 전체에서 "비용 지불"이라는 모호한 용어가 "은행에 납부"로 통일된다
- **SC-004**: [Optional] 건물 유형(호텔/빌딩/별장)이 시각적으로 구분되어 표시된다 (US3 구현 시)

# Feature Specification: Game Connectivity

**Created**: 2026-01-23  
**Status**: Draft

## Clarifications

### Session 2026-01-23

- Q: 재접속한 플레이어가 원래 플레이어인지 어떻게 식별할까요? → A: 닉네임 + 방 코드 조합으로 식별 (재접속 시 방 코드 필요)
- Q: 호스트 연결 끊김 후 얼마 후에 호스트 이전을 실행할까요? → A: 2분 대기 후 이전 (재접속 기회 부여)
- Q: 강제 퇴장된 플레이어의 자산을 어떻게 처리할까요? → A: 자산 말소 (현금/부동산 모두 삭제), 강제 퇴장 조건은 5분 이상 오프라인

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 연결 상태 실시간 표시 (Priority: P1)

게임 중 각 플레이어의 연결 상태(온라인/오프라인/재연결 중)가 실시간으로 화면에 표시되어, 다른 플레이어들이 현재 누가 접속 중인지 즉시 알 수 있다.

**Why this priority**: 연결 상태 정보는 모든 연결성 기능의 기반이 되며, 사용자가 게임 진행 상황을 이해하는 데 필수적이다.

**Independent Test**: 로비 또는 대시보드에서 각 플레이어 옆에 연결 상태 아이콘이 표시되고, 연결이 끊기면 즉시 상태가 변경되는 것을 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 게임이 진행 중일 때, **When** 플레이어가 정상 접속 중이면, **Then** 해당 플레이어 옆에 녹색 "온라인" 상태가 표시된다
2. **Given** 게임이 진행 중일 때, **When** 플레이어의 연결이 끊기면, **Then** 3초 이내에 해당 플레이어의 상태가 "오프라인" 또는 "연결 끊김"으로 변경된다
3. **Given** 플레이어가 오프라인 상태일 때, **When** 해당 플레이어가 재접속을 시도하면, **Then** "재연결 중" 상태가 표시된다

---

### User Story 2 - 재접속 및 세션 복원 (Priority: P1)

플레이어가 네트워크 문제 등으로 연결이 끊긴 후, 일정 시간(유예 기간) 내에 같은 닉네임과 방 코드로 같은 방에 재접속하면 이전 현금/자산 상태가 그대로 복원된다.

**Why this priority**: 실제 게임에서 가장 자주 발생하는 문제이며, 이를 해결하지 않으면 연결 끊김 시 게임 진행이 불가능해진다.

**Independent Test**: 플레이어가 브라우저를 닫거나 네트워크가 끊긴 후 재접속하여 이전 상태가 유지되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 플레이어 A가 현금 100만원, 자산 50만원 상태에서 연결이 끊겼을 때, **When** 5분 이내에 같은 닉네임과 방 코드로 재접속하면, **Then** 현금 100만원, 자산 50만원 상태가 복원된다
2. **Given** 플레이어 A의 연결이 끊긴 지 5분이 초과되었을 때, **When** 재접속을 시도하면, **Then** 방에서 제거된 상태이며 새로운 플레이어로 입장해야 한다
3. **Given** 유예 기간 내에 재접속 시도 중일 때, **When** 다른 플레이어들에게, **Then** "플레이어 A 재연결 중..." 알림이 표시된다

### User Story 3 - 호스트 이전 (Priority: P2)

호스트가 연결이 끊기고 2분이 경과하면 자동으로 다음 플레이어에게 호스트 권한이 이전되어 게임이 중단되지 않는다.

**Why this priority**: 호스트 연결 끊김 시 게임 전체가 중단되는 것을 방지하여 게임 안정성을 보장한다.

**Independent Test**: 호스트가 게임을 나가거나 연결이 끊겼을 때 다른 플레이어가 자동으로 호스트가 되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 호스트(플레이어 A)와 참가자(플레이어 B, C)가 있는 게임 중일 때, **When** 호스트의 연결이 끊기고 2분이 경과하면, **Then** 가장 먼저 입장한 참가자(플레이어 B)가 새로운 호스트가 된다
2. **Given** 호스트 이전이 발생했을 때, **When** 모든 플레이어에게, **Then** "플레이어 B가 새로운 호스트가 되었습니다" 알림이 표시된다
3. **Given** 새로운 호스트가 된 플레이어 B에게, **When** 호스트 권한이 부여되면, **Then** "게임 종료" 버튼이 표시되고 호스트 전용 기능을 사용할 수 있다
4. **Given** 호스트가 2분 이내에 재접속하면, **When** 호스트 이전이 발생하지 않고, **Then** 기존 호스트가 권한을 유지한다

---

### User Story 4 - 플레이어 강제 퇴장 (Priority: P3)

호스트는 5분 이상 연결이 끊긴 플레이어를 방에서 강제 퇴장시킬 수 있다.

**Why this priority**: 장시간 오프라인 상태인 플레이어로 인해 게임 진행이 방해받는 것을 방지한다.

**Independent Test**: 호스트가 오프라인 플레이어를 선택하여 강제 퇴장시키고, 해당 플레이어의 슬롯이 비워지는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 플레이어 A가 5분 이상 오프라인 상태일 때, **When** 호스트가 해당 플레이어의 "강제 퇴장" 버튼을 클릭하면, **Then** 확인 모달이 표시된다
2. **Given** 확인 모달에서 "확인"을 선택하면, **When** 퇴장이 실행되고, **Then** 해당 플레이어는 방에서 제거되며 현금과 부동산 자산이 모두 말소된다
3. **Given** 강제 퇴장이 완료되면, **When** 모든 플레이어에게, **Then** "플레이어 A가 퇴장되었습니다" 알림이 표시된다
4. **Given** 강제 퇴장된 플레이어가 재접속을 시도하면, **When** 새로운 플레이어로 입장하며, **Then** 이전 현금/자산은 복원되지 않는다

---

### User Story 5 - 자동 재연결 (Priority: P3)

연결이 끊긴 경우 클라이언트가 자동으로 재연결을 시도하고, 사용자에게 재연결 진행 상황을 표시한다.

**Why this priority**: 일시적인 네트워크 문제로 인한 연결 끊김을 사용자 개입 없이 자동으로 복구한다.

**Independent Test**: 네트워크를 일시적으로 끊었다가 복구했을 때 자동으로 재연결되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 플레이어가 게임 중일 때, **When** 네트워크가 일시적으로 끊기면, **Then** "연결 끊김. 재연결 시도 중..." 메시지가 표시되고 자동으로 재연결을 시도한다
2. **Given** 자동 재연결이 성공하면, **When** 연결이 복구되고, **Then** "연결 복구됨" 메시지가 표시되며 이전 상태로 게임이 계속된다
3. **Given** 5회 재연결 시도가 모두 실패하면, **When** 재연결 포기 후, **Then** "연결 실패. 새로고침하여 재접속해주세요" 메시지와 함께 새로고침 버튼이 표시된다

---

### Edge Cases

- **동시 재접속**: 같은 닉네임으로 두 세션이 동시에 접속 시도하면 먼저 연결된 세션만 유효하며 나중 세션은 거부된다
- **호스트 이전 중 원래 호스트 복귀**: 호스트 이전 대기(2분) 중 원래 호스트가 재접속하면 호스트 이전이 취소되고 기존 호스트가 권한을 유지한다. 이미 이전이 완료된 경우 원래 호스트는 일반 참가자로 복귀한다
- **모든 플레이어 연결 끊김**: 모든 플레이어가 오프라인 상태가 되면 방은 유예 기간(5분) 동안 유지되며, 유예 기간 초과 시 방이 삭제된다
- **강제 퇴장된 플레이어의 자산 처리**: 강제 퇴장된 플레이어의 현금과 부동산 자산은 모두 말소된다 (게임에서 완전히 제거)

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 시스템은 각 플레이어의 연결 상태(온라인/오프라인/재연결 중)를 실시간으로 표시해야 한다
- **FR-002**: 시스템은 연결 상태 변경 시 3초 이내에 모든 클라이언트에 반영해야 한다
- **FR-003**: 시스템은 연결이 끊긴 플레이어의 세션 정보(현금, 자산, 닉네임)를 유예 기간(5분) 동안 보존해야 한다
- **FR-004**: 시스템은 닉네임 + 방 코드 조합으로 재접속 플레이어를 식별하고, 유예 기간 내 재접속 시 세션을 자동 복원해야 한다
- **FR-005**: 시스템은 호스트 연결 끊김 후 2분 경과 시 입장 순서에 따라 다음 플레이어에게 호스트 권한을 자동 이전해야 한다
- **FR-006**: 호스트는 5분 이상 오프라인 상태인 플레이어를 강제 퇴장시킬 수 있어야 한다
- **FR-007**: 강제 퇴장된 플레이어의 현금과 부동산 자산은 모두 말소되어야 한다
- **FR-008**: 클라이언트는 연결 끊김 감지 시 자동으로 최대 5회 재연결을 시도해야 한다
- **FR-009**: 시스템은 호스트 이전, 플레이어 퇴장 등 중요 이벤트 발생 시 모든 플레이어에게 알림을 표시해야 한다

### Key Entities

- **PlayerSession**: 플레이어의 접속 상태, 마지막 접속 시간, 현금, 자산, 닉네임, 방 코드 정보를 포함하는 세션 정보
- **ConnectionStatus**: 온라인(ONLINE), 오프라인(OFFLINE), 재연결중(RECONNECTING) 상태 값
- **GracePeriod**: 재접속 허용 시간(5분)
- **HostMigrationDelay**: 호스트 이전 대기 시간(2분)

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 연결 끊김 발생 시 3초 이내에 다른 플레이어들에게 상태 변경이 표시된다
- **SC-002**: 자동 재연결 시도는 평균 5초 이내에 첫 시도가 시작된다
- **SC-003**: 유예 기간 내 재접속한 플레이어의 95% 이상이 이전 상태를 성공적으로 복원한다
- **SC-004**: 호스트 연결 끊김 시 2분 대기 후 새로운 호스트가 지정된다
- **SC-005**: 연결 관련 문제로 인한 게임 중단 사례가 현재 대비 80% 감소한다
- **SC-006**: 재연결 성공률이 80% 이상이다 (일시적 네트워크 문제의 경우)

## Assumptions

- 유예 기간(Grace Period)은 5분으로 설정한다
- 호스트 이전 대기 시간은 2분으로 설정한다
- 재접속 플레이어 식별은 닉네임 + 방 코드 조합으로 수행한다
- 호스트 이전 시 입장 순서(가장 먼저 입장한 순)에 따라 우선권이 부여된다
- 자동 재연결은 최대 5회 시도하며, 각 시도 간격은 2초, 4초, 8초, 16초, 32초로 지수적으로 증가한다
- 강제 퇴장 기능은 5분 이상 오프라인 상태인 플레이어에게만 활성화된다
- 강제 퇴장된 플레이어의 현금과 부동산 자산은 모두 말소된다
- 방의 모든 플레이어가 오프라인 상태가 되어도 유예 기간 동안 방 데이터는 유지된다
